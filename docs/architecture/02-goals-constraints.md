# 02 目标、约束与质量（arc42 §1 §2 §10）

## 目标

1. **一个插件闭环**：鉴权（复用浏览器登录态）、抓取、分析、可视化、AI 解读都在同一个扩展里完成，零后端、零手动导 Cookie。
2. **两种分析粒度**：单个视频的评论区全量分析；任意一条评论及其回复树的单独分析。
3. **平台可扩展**：新增平台只需实现 `PlatformAdapter`（`src/core/platform.ts`）并登记到 `src/platforms/index.ts`，引擎 / UI / AI 不改。

## 约束

| 类别 | 约束 |
|---|---|
| 运行环境 | Chrome / Edge ≥ 116（MV3、Side Panel、`world: "MAIN"` 内容脚本、DNR 会话规则）。 |
| 平台风控 | B 站匿名顶层分页可能被截断为 3 条热评，也实测返回过完整分页；不能把匿名请求成功当成全量证明。评论树需遍历 reply/detail 游标并报告数量差异；删除、隐藏、风控导致的缺失不能还原。 |
| 平台礼貌 | 每平台并发与最小请求间隔由适配器声明（B 站：并发 3、间隔 250 ms）；重试指数退避 1 s 起、30 s 封顶、最多 5 次。 |
| 凭据 | Cookie 只由浏览器随请求携带，扩展不读取、不存储；AI 密钥只存 `chrome.storage.local`，不进日志 / 缓存键 / 快照。 |
| 规模上限 | 默认全量遍历（0 表示不限）；可主动设置正数上限，超限必须标记不完整。 |
| 工具链 | TypeScript 6（vue-tsc 依赖 TS JS API，TS 7 原生版暂不可用）、Vue 3、Vite、Vitest。 |

## 质量场景

| 场景 | 期望行为 |
|---|---|
| 用户二次点击“分析” | 可满足当前范围的快照直接重算报告，不发平台请求；记录抓取时间，不冒充最新数据。 |
| 选择"增量刷新" | 重新遍历顶层分页，只重抓 `replyCount` 变化的评论树；进度里可见请求数与缓存命中数。 |
| 在评论区报告里点某条评论"分析此评论树" | 若主体快照已含该树完整回复，零请求直接出树报告。 |
| 抓取中触发风控 | 自动退避并在进度条显示等待倒计时；超过重试上限给出失败原因与补救（登录 / 稍后重试）。 |
| IndexedDB 损坏或配额满 | 分析照常完成（降级为内存缓存），缓存面板 `degraded` 计数上升。 |
| 大评论树展示 | Canvas 绘制与视口裁剪；评论列表虚拟滚动。吞吐与交互延迟需以实际运行测量为准。 |
