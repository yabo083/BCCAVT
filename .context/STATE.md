## 热度序成链缓存 · 完整度 · 412（2026-10-30 落地，未发版）

**三处根因（都经真机/接口实测，不是推断）**：
1. **热度序的翻页位置是平台侧会话，不是 offset**：登录态下 `wbi/main` 把同一个 offset 连发多次、在服务端会话里逐块推进（`offset=""` 开新会话并回榜首；同一 offset 连发依次 18/20/6/0 条后 `is_end`；隔 60s 重发仍从**会话当前进度**继续，不回放上一块）。所以按 offset 缓存会把第一块反复喂回来，按 offset 判断环又会误判成「到底」。
2. **「不完整」是判据错，不是少数据**：平台声明数含楼中楼的全部后代，根评论 `replyCount` 只算直接回复 ⇒ `Σ(1+replyCount)` 恒小于声明数（BV13PshzEEFd：64 根 + 直接回复 44 = 108，声明 191，差的 83 是二级以后）。两种排序在该视频都只回 64 条根评论（= 原生 DOM 的 64 个 `bili-comment-thread-renderer`），数据本来就全。
3. **412 的主因之一是交互请求绕开了令牌桶**：旧 `acquire('interactive')` 是「有令牌就拿，没有也放行」，快速滚动时阅读器完全不限速；AIMD 封顶 4 rps 也远超真人节奏。

**落地**：
- `crawl.ts#loadHotRootsPage`：热度序游标改成自己的 `hot:<会话 id>:<块号>`，块按 (会话, 块号) 入页缓存；`offset=""` 才开新会话；平台说完（`is_end` 或零条块）后链记为 ended，界外页不回源；块被淘汰 → 弃链重开；续块整页都是首块条目 = 会话被平台重置 ⇒ 开新会话重来（不让首块冒充第 N 块）。
- `EmbeddedComments.vue#completeness`：完整度只认平台「还有没有下一页」，声明数只在气泡里解释数字差在哪；顶栏与列表头统一显示平台声明总数；`commentCount` 改成**顶层**评论数（条目里夹着楼中楼预览）。
- `rate-limit.ts`：交互请求也排队（水位线：交互 1、批量 1+reserve）、AIMD 封顶 4→2、等待 ±15% 抖动、风控冷却起点 30s→60s。`EmbeddedComments.vue#noteRateLimited`：412 显示倒计时并到点自动重试，连续 4 次仍限流才交回「重试」。

**验证**：`npm test` 52 文件 / 767 项、`vue-tsc --noEmit`、`npm run build` 全过。真机（调试 Chrome、已登录、BV13PshzEEFd，191 条评论）：
- 最热滚到底：64 条根评论 / 108 行（含楼中楼预览）、徽章**完整**、气泡「平台声明 191 条评论（含楼中楼的全部回复）；顶层 64 条根评论已全部取回」、尾行「没有更多评论了」。
- 切「最新」（4 次 `mode=2` 请求，同样 64 条根）再切回「最热」：**0 回源**，64 根 / 108 行、徽章完整、位置不变。
- 重开视频页（新阅读器实例、缓存仍在）：首屏 53 行从缓存回放，滚到底 64 根，**整条链 0 回源**。
- 本轮全程未触发 412；限流路径由单测覆盖（`embedded-comments-reader.test.ts` 的 412 用例：倒计时文案 → 到点自动重试 → 行出现）。
- **探针纪律**：`chrome.runtime.reload()` 会把扩展打成 `chrome-error://chromewebdata/`（页面全 404），换 bundle 一律**重启浏览器**（只杀 `--user-data-dir=…tmp\chrome-login` 那棵树，别误杀用户自己的 Chrome）。

## 第二刀：预取提前量 + 分层 TTL（2026-10-30，未发版）

第一刀之后用户点名的欠账，按性价比取前两条（其余仍空账，见 `roadmap.md` 2.4.0 第 2 条）：

- **距底一屏预取**：`READER_VIEWPORT` 多带 `viewportHeight`（`page-reader.ts#postViewport`），阅读器 `prefetchMargin = max(480, viewportHeight)` 同时用于触发判定与哨兵几何。边沿触发不变，单飞不变，请求数不变，只把下一页的 RTT 藏进用户还在滚的那一段。
- **分层 TTL**：`Freshness` 加 `history`（12 小时）。时间序首屏 `page`（30 分钟）／更深页 `history`；热度序块 `history`、链记录「未走完 `page` / 走完 `history`」。于是「回看已读的旧区间」不再受 30 分钟限制，完整的热度榜快照整天可回放。
- **会话寿命实测（20 分钟探针，BV13PshzEEFd）**：先取 A/B/C/D 四块记住 id，等满 20 分钟再用 D 的 offset 续 ⇒ 返回 19 条**全是 B 块原内容**；用更老的 offset 续 ⇒ 返回 A 块（榜首）。结论：平台会话过期后不是「续上/报错」，而是**回放到某个旧块**；跨 20 分钟的续接不可信。
- **会话续接的守卫**：链记录存 `seenIds`（这条链已收下的全部条目 id），续块时**任一 id 重合**即判平台重置（不只榜首，中间块也算）。认出重置后**开新会话 + 快进跳过重合块**（至多 3 块），交出第一页带新条目的内容；额度用完仍全是旧内容则返回 `endReason`「平台的热度序会话已失效，剩下的评论请点刷新重新拉取」，阅读器据此显示**不完整**并说明原因（不假装到底）。未走完的链记录因此只给 30 分钟寿命。
- **多标签页同视频**：热度序整段取数落在 `loupe-hot|<subject>|<account>` 的 Web Lock 里，两个阅读器不再互相覆盖链指针。
- **快照如实标注**：整条热度序快照回放超过 5 分钟时，完整度气泡写「这是 N 分钟前读取的快照（点刷新可重新拉取）」；实时页不标。

- **回复分页也分层**：`crawlThreadPages` 首屏 `page`、更深页 `history`（新回复同样只进顶部）。
- **首屏不等评论树**（`CrawlOptions.includeThreads=false`，阅读器专用）：冷缓存第一次进视频实测 **8.9 s → 2.6 s**，`detail` 请求 **13 → 0**。根因是逐页取数时给「声明回复数 > 内联预览数」的每一条根评论各发一次 `detail`（1 rps 排队 ≈ 6 s），而那些回复要展开才看得到。分析/快照路径仍走 `includeThreads` 缺省 true（成品数据集要补齐评论树）。
- **菜单图标**：评论区操作行「更多」从横排三点换成竖排（`ph:dots-three-vertical`），与站内其他竖向菜单一致。
- **工作台顶栏参数行重排**：`PalettePicker` 从顶栏移除（唯一入口回到设置弹窗，工作台改由 `src/ui/main.ts`（挂 `watchPalette`） 跟随存储事件）；删掉「登录态/匿名」文字（`SessionChip` 已经表达身份）；顺序改为 **数据源（图标+名字）→ 评论数·参与者数（主文字）→ 节点·边（紧随其后的小号衬影文字）→ 完整度 → 抓取于 → 状态 chip 收尾**。真机（1440×900、`maxRoots 5` 的小规模分析）读到：`评论区回复图 · 5 条评论 · 5 位参与者 · 5 节点 · 0 边 · 不完整 抓取于 刚刚 已收敛`，顶栏内 palette 元素计数 0。
- **收起详情改成与其余三块浮岛同规格**：撤掉「贴壁」的负外边距，把手恢复 `--r-md` 四面圆角 + 四面描边，留在浮层 12px 内边距里（真机 `right = innerWidth - 12`）。贴壁版本在四块浮岛之间显得是另一个体系，用户否掉。
- **参数行数字改成轮播**：`X 条评论 · Y 位参与者` 与 `M 节点 · N 边` 收进同一格轮播（6 秒淡入淡出、悬停暂停、`prefers-reduced-motion` 下平铺），格子宽度取两片最大值所以不跳版；四个数字平铺在窄窗口下太长。
- **完整度徽标自己就是气泡触发器**：去掉旁边的第二个 ⓘ（一行两个图标看着重复），解释仍在气泡里；阅读器同步。
- **「抓取于」会走时**：原来模块内没有时钟，快照不变就一直显示「刚刚」。现在 30 秒推一次 `nowTick`，`formatRelative` 按它算（真机：等过一分钟变成「1 分钟前」）。

验证：`npm test` 52 文件 / **776 项**、`vue-tsc --noEmit`、`npm run build`、`docs:check` 全过（新增：分层 TTL 跨 30 分钟仍命中、中间块重置守卫、快进交出首块新内容、快进耗尽给 `endReason`、快照时刻、预取提前量与边沿触发）。真机（清空缓存后重跑 BV13PshzEEFd，191 条评论）：

## 第三刀：楼中楼自动补全 + 按页取（2026-10-30）

用户两条反馈：① 楼中楼要「二次点击 fold-act」才完整加载（第一次点只是折叠，第二次才回源）；② 但也不能一次全抓——原生楼中楼分页是有道理的。

- **自动补全**：可视带（宿主视口上下各留一屏 + 600px）里的根评论自动抓第一页回复，抓回原地铺开。边沿：折叠过的（含「全部折叠」）不碰；已取到窗口/到底/在途的不重复请求；每轮最多起 3 棵。触发来自 `evaluateTrigger`（视口消息、取数落定）与 `listEntries` 长度变化（新行渲染不会让宿主重发视口消息，少了这一下要等用户再滚一下）。真机（BV13PshzEEFd）：首屏 19 根 + 14 条回复 / 3 次 `detail`；滚一段 100 行 / 11 次；**停 8 秒请求与行数都不再增长**。
- **按页取**：每棵树一次只取 `REPLY_PAGE = 20` 条；树尾一枚内容宽度的小胶囊「还有 N 条回复」（带图标、`align-self: flex-start`，实测 95px vs 列表 620px），点一次多取一页。
- **「点了没反应」的真因**：剩余数按平台声明的 `replyCount` 算，而声明常大于实际可取数（删除 / 折叠 / 权限），于是永远剩几条、点下去什么都不发生。现在按事实判到底：一次要 `target` 条只回来更少 ⇒ 这棵树记为 `exhausted`，树尾入口消失、行按钮也不再显示「展开」。真机：点「还有 5 条回复」→ 行 72→74、该棵树的入口消失，「还有」条目数 10→9。
- **`toggleFold` 语义修正**：回复还没取过时，第一下点击就是「去取回复」，不是「先把预览收起来」（旧行为要折叠→展开两下才回源）。

验证：`npm test` 52 文件 / **782 项**、`vue-tsc --noEmit`、`npm run build`、`docs:check` 全过（新增：自动补全、全部折叠优先、按页取 20→40、声明多于实际不出入口）。

## 真机验收方法（本机可复现；细节与坑见 `LESSONS.md`）

1. 起一个**专用 profile** 的 Chrome（`--user-data-dir=tmp/...`，不要用用户日常 profile），扩展用 CDP `Extensions.loadUnpacked` 装 `dist/`（Chrome 137+ 起 `--load-extension` 命令行开关已失效）。
2. 在设置弹窗里打开「自绘评论区（替换原生）」开关；打开一个视频页，**先 `bringToFront()` 并暂停 video**（后台标签页不渲染：`ResizeObserver`/`IntersectionObserver`/滚动都不生效；视频播完会触发站点自己的平滑回顶，污染滚动观测）。
3. 探针要装在 `tab.run`（`page.mainFrame().evaluate`）那个 JS world：实测 `t.evaluate` 与它互不可见，且 reader 的 postMessage 只在前者里被收到。
4. 要验真实抓取量必须带登录态：匿名评论 API 只回 3 条。用测试 profile 前先注入 cookie，用完**删除该 profile**。
5. 断言看三样：桥请求 URL 是否**逐页唯一**、到底之后是否**零新增请求**、高度上报是否**单调不减**。
